# フィードバック通知

フィードバックを保存した後、`carpool.app.2026@gmail.com` から同じアドレスへ通知を送信する。
件名にカテゴリと受付番号、本文に受付日時（日本時間）・返信先・投稿内容を掲載する。
返信先があるときはメールの返信ボタンで投稿者に返信できる。

## 本番設定

VercelのCarpoolプロジェクトで、Productionのみに次の環境変数を設定し、再デプロイする。

- `CARPOOL_GMAIL_APP_PASSWORD`: CarpoolのGoogleアカウントで作成したアプリパスワード。
  通常のログインパスワードは使用しない。チャットやリポジトリには記載しない。

Googleアカウント側での認証・アプリパスワードの発行と、Vercelの値入力は管理者が行う。
既存のSupabase認証メールの設定変更は不要。
PreviewやDevelopmentには本番メール用のパスワードを設定しない。

- `CARPOOL_FEEDBACK_OPERATOR_EMAIL`: 運営用受信箱を閲覧する、Carpool管理画面のログインメール。
  サーバー側のProduction環境変数として設定する。未設定なら受信箱は誰にも表示されない。
  通知用のGmailアドレスが管理画面のログインアカウントとは限らないため、実際のログインメールを指定する。

受信箱のリリースでは、先に `20260929000000_add_feedback_inbox` マイグレーションを適用し、その後に新コードを公開する。

## 検証と障害時

本番フォームから「通知動作確認」と明記して1件送信し、Gmailで本文・返信先・日本時間の受信を確認する。
テストは実際のFeedbackレコードとして保存される。

通知に失敗した場合も投稿は保存され、受付は成功扱いになる。
Vercelのログに `[feedback-notification] delivery_failed` と受付番号を記録する。
通知処理の結果は `Feedback.notificationStatus` に `accepted` / `failed` として保存する。
失敗時は許可したエラーコードと数値のSMTP応答コードだけを保存し、本文や認証情報は診断欄に残さない。
`accepted` はSMTPサーバーでの受付を示し、実際のGmail受信を保証しない。
既存投稿は結果を判定できないため `unknown` にする。処理が中断された投稿は `pending` のまま残る。
自動再送は行わない。運営用 `/admin/feedback` で未確認投稿と通知状態を確認する。
SMTPでの受付成功とGmailでの実際の受信は別に確認する。
